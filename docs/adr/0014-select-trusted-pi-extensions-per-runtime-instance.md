# Select trusted Pi extensions per runtime instance

Each Pi runtime instance carries a T3 Code owned trusted-extension selection: an explicit list of extension paths the user intentionally trusts, entered one per line in the runtime settings. T3 Code starts every Pi RPC session and model probe with `--no-extensions` so ambient global or project-local discovery cannot load, and adds one `--extension <path>` argument per selected trusted extension. Raw additional launch arguments cannot pass `--extension`; the trusted-extension selection is the only way to load a Pi extension through T3 Code. As a deliberate escape hatch, a `T3CODE_PI_EXTENSION` entry in the instance environment appends one extra trusted path after the settings selection, mirroring how Pi's own escape hatches work. Compatible confirm, select, and input dialogs from those explicit extensions continue to round-trip through T3 Code's user-request UX, unsupported custom extension terminal UI remains routed to Pi's terminal interface, and Pi `extension_error` events keep their extension path attribution so extension-induced tool failures are not confused with T3 Code transport failures.
